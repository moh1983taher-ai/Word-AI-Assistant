# ResearchTools MCP Host

مضيف محلي جديد لـ «أدوات الباحث»، مبني على .NET 10 LTS، ويستخدم مكتبة **Model Context Protocol C# SDK** الرسمية لإدارة عملاء MCP.

## النطاق الحالي

- خادم HTTP غير متزامن على 127.0.0.1:18081 افتراضياً، مع خيار تغيير المنفذ للاختبار.
- يحافظ على واجهات التوافق مع إضافة Word الحالية: /ping و/health و/v1/models و/v1/research.
- واجهة /v1/mcp/sources تختبر اكتشاف الأدوات وتعرض حالة الجامع والشاملة وعدد الأدوات المتاحة.
- يتصل بالجامع الرسمي عبر https://aljam3.com/mcp وبالمكتبة الشاملة عبر https://mcp.shamela.ws.
- يستخدم نقل SDK التلقائي: Streamable HTTP أولاً ثم SSE عند الحاجة، مع التفاوض التلقائي على إصدار البروتوكول.
- يكتشف واجهة DuckAI على المنفذين 18080 و8080. إذا نجح عرض النماذج وفشل التوليد في الواجهة الأولى بـ 502/503/504 أو تعذر الاتصال، ينتقل تلقائياً إلى الواجهة المحلية الأخرى، ثم يحفظ آخر واجهة نجحت في التوليد لاستخدامها لاحقاً. فحص /health يوضح عنوان الواجهة التي نجحت في عرض النماذج فقط، ولا يدّعي نجاح التوليد قبل تجربة الطلب. وبسبب أن endpoint المثبّت أعاد نصاً عادياً حتى عند فرض استدعاء وظيفة محددة، يستخدم المضيف بروتوكول قرارات JSON منذ أول دورة؛ فيختار النموذج أداة MCP ومعاملاتها من الفهرس، ويتحقق المضيف منها ثم ينفذها عبر SDK الرسمي. لا تُعد الإجابة بحثاً موثقاً في الطلبات التي تطلب مصادر أو مراجع ما لم ينجح تنفيذ أداة MCP واحدة على الأقل.
- يحتفظ بفهرس الأدوات خمس دقائق، ويسمح بطلبين متزامنين. لا يفرض عددًا أقصى ثابتًا لاستدعاءات الأدوات، ولا يشترط استخدام كل مكتبة اختارها المستخدم؛ يقرر النموذج متى يواصل البحث ومتى ينهيه.
- يحد سياق المحادثة المرسل إلى DuckAI بـ20,000 حرف في كل دورة توليد، مع سقف 12,000 حرف للرسالة الواحدة. يحتفظ بطلب المستخدم الحالي ويُبقي أحدث الرسائل ونتائج الأدوات ضمن الحد، ويعيد تطبيق الحد قبل كل استدعاء للنموذج؛ ولا يحذف أو يغيّر أي رسالة من سجل Word الأصلي.
- لا يتيح أدوات الكتابة أو التعديل أو الحذف، ويتحقق محلياً من الحقول المطلوبة وأنواع المدخلات قبل إرسال الاستدعاء.
- فحص الحياة /ping مستقل عن مهام البحث الطويلة، ولا يقرأ محتوى الطلبات في سجل التشخيص.

## تشغيل محرك MCP الأصلي في LM Studio

يدعم المضيف محركين مستقلين:

- **DuckAI** هو المسار الافتراضي، ويحافظ على التوافق مع النسخة الحالية وبروتوكول قرارات JSON.
- **LM Studio** مسار اختياري يستخدم واجهة LM Studio الأصلية `/api/v1/chat`، ويترك له إدارة دورة MCP كاملة: عرض الأدوات، اختيارها، تنفيذها، إعادة النتائج إلى النموذج، ثم توليد الإجابة النهائية.

يتطلب مسار LM Studio إصدار 0.4.0 أو أحدث، ونموذج لغة يدعم استخدام الأدوات. فعّل في إعدادات خادم LM Studio خيار **Allow per-request MCPs**. لا يحتاج المستخدم إلى إضافة الجامع أو الشاملة يدوياً إلى ملف `mcp.json`؛ يمرر المضيف الخادمين المختارين لكل طلب على حدة.

لتفعيل المسار على الجهاز المحلي، أضف متغيرات البيئة التالية إلى حساب Windows الذي يشغل المضيف، ثم أعد تشغيل Word والمضيف:

~~~powershell
[Environment]::SetEnvironmentVariable('RESEARCHTOOLS_AGENT_PROVIDER', 'lmstudio', 'User')
[Environment]::SetEnvironmentVariable('RESEARCHTOOLS_LMSTUDIO_BASE_URL', 'http://127.0.0.1:1234', 'User')
~~~

إذا كان خادم LM Studio يتطلب رمز وصول، أضف:

~~~powershell
[Environment]::SetEnvironmentVariable('RESEARCHTOOLS_LMSTUDIO_API_TOKEN', 'YOUR_LOCAL_API_TOKEN', 'User')
~~~

للعودة إلى DuckAI:

~~~powershell
[Environment]::SetEnvironmentVariable('RESEARCHTOOLS_AGENT_PROVIDER', 'duckai', 'User')
~~~

المتغيرات الثلاثة لا تُرسل إلى الويب ولا تُخزن في المستودع. يقبل المضيف عنوان LM Studio على loopback فقط، ويستخدم قائمة أدوات القراءة التي اكتشفها بنفسه بعد تطبيق `ToolPolicy`، ويمرر أسماء تلك الأدوات تحديداً في `allowed_tools`. لا يُسمح للموديل بالاتصال بمكتبة لم يخترها المستخدم. يحتفظ المضيف بمخرجات استدعاءات الأدوات التي تصل عبر بث SSE، ويراجع أن هوية الخادم والأداة تطابق الفهرس المختار قبل إدراجها في سجل الأدلة.

يمكن التحقق من حالة المحرك عبر `/health`، واسترجاع النماذج المتاحة عبر `/v1/models`. لا يثبت نجاح فحص النماذج قدرة النموذج على استدعاء الأدوات؛ لذلك يجب إجراء بحث فعلي على سؤال اختباري بعد التفعيل. اختيار نموذج لا يعلن عن تدريبه لاستخدام الأدوات ينتج تحذيراً، ولا يمنع المحاولة.

## اختبار النسخة محلياً دون المساس بالخدمة الحالية

تحتوي حزمة Windows على الملف Start-McpHost-Preview.ps1. هذا هو الملف الوحيد الذي تحتاج إلى تشغيله للتجربة؛ فهو يطلق المضيف الجديد مؤقتاً على منفذ 18082، ويختبر DuckAI ومصدري MCP وتنفيذ بحث فعلي واستجابة /ping أثناء البحث، ثم يغلق العملية التجريبية وحدها. يبقى الجسر الحالي على 18081 كما هو.

من PowerShell داخل مجلد الحزمة:

~~~powershell
.\Start-McpHost-Preview.ps1
~~~

يمكن تخصيص سؤال البحث:

~~~powershell
.\Start-McpHost-Preview.ps1 -Question 'ابحث في المكتبة الشاملة عن ...'
~~~

إذا أظهر الاختبار نجاح اكتشاف المصادر ولكنه لم يسجل أي استدعاء أداة، فهذا يعني أن النموذج لم يستخدم وظيفة MCP في تلك المحاولة، ويجب ألا نعدّ ذلك اختبار بحث ناجحاً.

## البناء والاختبار

يتطلب .NET 10 SDK:

~~~powershell
dotnet restore runtime/McpHost.Tests/ResearchTools.McpHost.Tests.csproj
dotnet test runtime/McpHost.Tests/ResearchTools.McpHost.Tests.csproj --configuration Release
dotnet publish runtime/McpHost/ResearchTools.McpHost.csproj --configuration Release --runtime win-x64 --self-contained true -p:PublishSingleFile=true
~~~

يتحقق سير GitHub Actions من البناء واختبارات الوحدات، ثم يشغّل المضيف على Windows runner ويتأكد من اكتشاف الأدوات المتاحة في المصدرين قبل نشر الملف التنفيذي كأثر بناء.

## حالة الدمج

هذه نسخة تطوير مستقلة. لا تستبدل المشغّل أو الجسر الحاليين، ولا تعدّل معرّف إضافة Word أو إعداداتها. لا يجوز الانتقال إلى اعتمادها في التثبيت التلقائي قبل اجتياز CI، ثم اختبار التكامل على Windows مع نسخة DuckAI الفعلية وخادمي MCP.
